# 05 · 技术架构与演示

## 架构范式：完全复用座舱四进程模式

每个垂直产品 = `gateway + service + agent + client` 四进程，与 `examples/smart-cockpit` 一一对应：

| 座舱 | 晚晴·照护（care） | 晚晴伴（home） |
| --- | --- | --- |
| gateway :18888 | gateway :18890 | gateway :18891 |
| service :3010（车辆/音乐/秒杀工具 + SSE） | service :3110（房间/呼叫/用药工具 + SSE） | service :3111（问安/提醒/升级工具 + SSE） |
| agent :3020（A2A 工单编排） | agent :3120（工单编排） | agent :3121（关怀调度） |
| client :5173（一个 UI） | client :5175（/room 终端 + /station 大屏 + /family） | client :5176（/elder + /family） |

## 关键技术决策

1. **依赖解析**：client 的 package.json 用 `"qwen-audio-agent": "file:../../.."` 指向仓库根（座舱同款）；service/agent 是独立 npm 包（MCP SDK / A2A SDK / openai）；gateway 纯脚本（根目录 node_modules 可解析）
2. **前台组合**：`createGatewayApplication` + `createBackendAgentHost(createA2ABackendAdapter(agentCardUrl))`，环境隔离 `QWAUDIO_CONFIG_DIR=products/<x>/.runtime`——**不污染用户配置**（座舱同款，经验证可避开 `~/.config` 的 speech-to-speech 干扰）
3. **MCP 双面**：service 暴露 `/mcp/frontend`（挂到实时会话做前台工具）与 `/mcp/backend`（A2A agent 消费）；`surface-routing.json` 控制域走向
4. **语音提供方**：演示默认 DashScope（`QWEN_AUDIO_REALTIME_PROVIDER=dashscope`，key 由 `.env.local` 注入，gitignore）；本地 s2s（`ws://127.0.0.1:8765`）写进部署文档作为私有化叙事，切换只需改两个环境变量
5. **客户端语音栈**：改编座舱 `useVoiceSession`（636 行，GCP 会话 + 音频管线 + 播放回执），去掉座舱 persona 同步，保留 {voiceState, levels, activateVoice, sendInput}
6. **状态投影**：service `/api/state` + `/api/events`(SSE)，snapshot/subscribe 双通道（座舱同款）；老人端、大屏、家属端都是同一 state 的不同投影

## 目录规划

```
products/
├── docs/                          # 本文档集
├── care/                          # 晚晴·照护
│   ├── bootstrap/                 #   loadCareEnvironment / preflight
│   ├── gateway/server.mjs         #   createGatewayApplication 组合（A2A backend → agent:3120）
│   ├── service/                   #   server + care-service(状态机) + mcp-server + tools/{call,medication,room,activity,duty}
│   ├── agent/                     #   A2A server + 工单编排 executor + DashScope model
│   └── client/                    #   React+Vite：/room /station /family 三视图
└── home/                          # 晚晴伴（同构，业务件不同）
```

## 演示环境（一台 Mac）

```bash
# 0. 准备（一次性）
products/care/.env.local     # DASHSCOPE_API_KEY=...
products/home/.env.local     # 同上

# 1. 启动机构版（四进程）
npm run care --prefix products        # gateway+service+agent+client 并发
open http://localhost:5175/station    # 大屏（投到电视/副屏）
open http://localhost:5175/room/302   # 床头终端（全屏）

# 2. 启动居家版
npm run home --prefix products
open http://localhost:5176/family     # 家属端（手机窗口宽度）
open http://localhost:5176/elder      # 老人端（全屏）
```

前提：仓库根 `npm ci` 完毕；Mic 允许浏览器访问；录音演示建议外接麦克风贴近演示者。

## 与上游框架的关系

- 本目录所有代码只 import `qwen-audio-agent/*` 公开导出，不改框架源码；框架缺陷记录到 `products/docs/known-issues.md` 而不是就地修补
- 通用能力（老人音量 profile、唤醒词配置化等）成熟后回馈框架，做法参照 `branding/REBRAND.md` 的分层纪律
- 代码只存在于 `product/wanqing` 分支；dev 分支永不合入产品目录，避免打进 public 发版

## 已知边界（诚实清单）

- 演示级升级链路是内存态模拟，不含真实推送/电话；接 IM Push / SIP 属二期
- 终端心跳、多机构隔离（tenant）为 P1/P2
- VoiceMem 记忆在演示里以框架默认 markdown provider 起步，切换 VoiceMem 仅改 provider 配置
- DashScope 免费额度用尽会影响文本模型调用（记忆提炼/后台 Agent），演示前确认额度或充值
