# 03 · 晚晴·照护（机构版）产品设计

## 角色与界面清单

| 角色 | 界面 | 路由 | 设备形态 |
| --- | --- | --- | --- |
| 老人 | 房间终端 | `/room/:roomId` | 床头 10 寸屏 + 物理呼叫按钮 |
| 护理员 | 工单流（大屏内嵌 + 独立视图） | `/station`、`/station/tasks` | 站内大屏 / 手持平板 |
| 护士长/院长 | 护理站大屏 | `/station` | 站内 55 寸大屏 |
| 家属 | 家属端（复用居家版家属界面，只读） | `/family` | 手机浏览器 |

演示环境：一台 Mac 同时跑四进程，浏览器开两个窗口（大屏 + 终端）即可演示；终端窗口全屏模拟床头屏。

## 一、房间终端（老人每天面对的界面）

### 布局（竖屏 3:4，全屏无滚动）

```
┌──────────────────────────────┐
│  20:36   9月12日 周五   ☁️18° │  ← 顶栏：时间大字（≥48px）+ 天气（service 工具）
│                              │
│      ╭──────────────╮        │
│      │   呼吸圈/头像  │        │  ← 语音状态可视化：待机=静止柔光，
│      │   （奶奶专属）  │        │    聆听=呼吸圈扩大，思考=缓转，播报=波纹
│      ╰──────────────╯        │
│                              │
│   「王奶奶，晚上好」           │  ← 称呼来自记忆引擎（owner 档案）
│   想聊点什么，或者按下面的按钮    │
│                              │
│  ┌─────────┐  ┌─────────┐    │
│  │  💊     │  │  🔴     │    │  ← 两大常驻按钮（≥120px）：
│  │12点吃药 │  │ 呼叫护理 │    │    左=下一条用药提醒（到期变琥珀+响铃）
│  │ 还有5分 │  │         │    │    右=一键呼叫（按下即触发工单）
│  └─────────┘  └─────────┘    │
│                              │
│  最近的话：正看着呢，戏曲频道…   │  ← 会话摘要一横条（点击展开全转写）
└──────────────────────────────┘
```

### 关键交互

1. **免唤醒语音**：点呼吸圈或说"你好煤球"（沿用唤醒词）进入对话；老人端默认按住说话容易误触，采用"点击开始，静默自动结束"
2. **呼叫反馈三段式**（可信感的关键）：
   - 按下瞬间：按钮变红 + "已经知道了，别着急"
   - 工单派单：文案换成"已告诉小李护理员了，她马上过来"（人名来自排班数据）
   - 受理回投：大屏上被受理后，终端显示"小李已接到，正在过来"（SSE 回投，与座舱秒杀订单状态回投同一模式）
3. **用药提醒流**：到期前 5 分钟卡片变琥珀 → 到期响铃 + 全屏卡片"该吃降压药了，一杯温水" → 老人说"吃了"或点"我吃好了" → 语音确认写回 → 大屏与家属端同步变绿；10 分钟未确认 → 生成 P1 提醒工单给护理员
4. **夜间模式**：22:00-6:00 自动降亮度、只留呼叫按钮和呼吸圈，语音仍可用

### 语音域路由（surface routing）

| 域 | 走向 | 说明 |
| --- | --- | --- |
| 呼叫求助 | 后台（工单 Agent） | "我要喝水/厕所疼" → 意图分级（紧急/普通） |
| 用药确认 | 后台（写状态） | 确认结果写 service 状态存储 |
| 天气/时间 | 前台（service 工具） | 实时查询 |
| 戏曲/广播 | 前台（媒体工具） | 演示用播放列表模拟 |
| 闲聊/记忆问答 | 前台（框架记忆） | "我孙女叫什么" |

## 二、护理站大屏（院长每天看的界面）

### 布局（横屏 16:9，3 米可读）

```
┌────────────────────────────────────────────────────────────┐
│ 晚晴·照护   幸福里 3 楼     20:36   当班：小李 王姐 张工       │ ← 顶栏：楼层数 + 在岗
├──────────────────────────────────┬─────────────────────────┤
│  ▣ 301 王秀英  ●平安  💊✓        │  ⚡ 呼叫队列 (1)          │
│  ▣ 302 李建国  🔴呼叫 02:41      │  ┌─────────────────────┐ │
│  ▣ 303 张桂兰  ●平安             │  │ 302 李建国 · 想喝水   │ │
│  ▣ 304 陈阿婆  🟡提醒 12:00吃药  │  │ 等待 02:41 ▓▓▓▓░░   │ │
│  ▣ 305 赵德福  ●平安  💊待       │  │ [受理] [到房打卡]     │ │
│  ▣ 306 …                        │  └─────────────────────┘ │
│  （房间网格，每卡：房号+姓名+     │  📋 处理中                │
│    状态灯 + 下一条提醒）          │  ✅ 305 已送水 08:32     │
│                                 │  📊 今日：呼叫6 平均响应   │
│                                 │     3分12秒              │
├──────────────────────────────────┴─────────────────────────┤
│ 活动栏：14:00 手工课(5人报名) · 天气：明天多云 12-19°         │ ← 底栏滚动信息
└────────────────────────────────────────────────────────────┘
```

### 关键交互

1. **状态灯是主角**：红闪（呼叫中，卡片放大呼吸动效）> 琥珀（提醒到期未确认）> 绿（平安）> 灰（终端离线，10 秒心跳超时）
2. **受理**：点呼叫卡 [受理] → 工单状态 处理中 → 该房卡片变蓝闪"小李已受理"；[完成] → 回绿，写响应时长
3. **超时升级**：呼叫 3 分钟无受理 → 大屏该卡加"⚠️升级"角标 + 推护士长视图（状态机在 agent）
4. **声音提示**：新呼叫播放上行双音；升级播放三音警音（音量独立于 UI）
5. 大屏左下角固定"离线终端"角标（网络/心跳监控），P1

## 三、后台 Agent（工单编排）

工具面（service 后台 MCP）：`call_create` / `call_accept` / `call_complete` / `medication_confirm` / `duty_roster`（查当班人）/ `activity_signup` / `room_state`。

工单状态机：

```
新建(new) ─受理(accept)→ 处理中(accepted) ─完成(complete)→ 已完成(done)
   │ 3分钟无受理
   └──→ 已升级(escalated)→ 通知护士长 → 回到受理分支
```

Agent 技能（A2A skill 描述给框架的示例话术）："我要喝水"、"屁股疼"、"帮我报手工课"、"药我吃过了"。

## 四、数据模型（service 状态存储，演示用内存 + JSON 落盘）

```
Room { id, bed, resident: {name, preferredAddress, avatar}, state: safe|calling|reminder|offline, terminalHeartbeat }

DutyRoster { shift, staff: [{name, role}] }
Activity { id, title, time, attendees[] }
```

## 五、演示脚本（录视频用，约 3 分钟）

1. 开场：大屏全景 5 秒（六间房全绿，底栏滚动）
2. 对终端说"我要喝水" → 终端转写 + "已告诉小李护理员了" → 大屏 302 红闪入队
3. 大屏点 [受理] → 终端显示"小李已接到" → 大屏点 [完成] → 回绿，统计更新
4. 对终端说"该吃药了吗" → 播报用药计划并引导口头确认 → 大屏💊变绿
5. 对终端说"下午手工课帮我报个名" → 大屏活动栏人数 +1
6. （加分）呼叫后 3 秒内不受理 → 大屏弹"⚠️已升级护士长"
7. 结尾：家属端（同框架居家版界面）收到状态摘要推送
